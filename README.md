# VeloxDesk (ВелоксДеск)

Полнофункциональная система техподдержки (helpdesk / service desk): приём и обработка тикетов клиентов, живой чат с оператором, база знаний, SLA, отчётность, автоматизация и гибкая настройка прав доступа.

Состоит из двух приложений:
- **Клиентский портал** — куда клиенты заходят, чтобы зарегистрироваться, создать тикет и переписываться с поддержкой.
- **Операторское приложение** — рабочее место сотрудников поддержки и администраторов: очередь тикетов, чат, отчёты, настройки системы.

## О проекте

VeloxDesk — система для приёма тикетов клиентов и их обработки службой поддержки. Клиент создаёт тикет через веб-портал (или пишет на email — письмо само превращается в тикет), дальше вся переписка идёт в едином чате в реальном времени. Оператор видит очередь тикетов, отвечает, меняет статус/приоритет/исполнителя, использует заготовки ответов и внутренние заметки, которые клиент не видит. Администратор настраивает права доступа, SLA, автоматизацию, базу знаний и следит за качеством работы через отчёты.

Рассчитана на команду поддержки от нескольких до нескольких десятков операторов и клиентскую базу с большим числом одновременно активных пользователей — нагрузочно проверена на профиле ~1500 одновременных клиентов + 30 операторов.

## Технологии

| Слой | Технология |
|---|---|
| Backend | NestJS (TypeScript), Node.js 24 |
| База данных | PostgreSQL + TypeORM |
| Очереди задач | BullMQ (Redis) — надёжная доставка (email-уведомления, индексация, автоматизация) |
| Реалтайм | Socket.IO — чат, живые статусы, live-обновления списков |
| Поиск | Elasticsearch (русская морфология) — по тикетам и статьям базы знаний |
| Файлы | S3-совместимое хранилище (MinIO) — вложения к тикетам |
| Frontend | React + TypeScript + Tailwind CSS, Vite |
| Состояние на клиенте | Zustand (persist) + TanStack React Query |
| Почта | Nodemailer (исходящие уведомления) + IMAP-поллинг (входящие письма → тикеты) |
| 2FA | TOTP (Google/Microsoft Authenticator и любой совместимый) |
| Мониторинг | Prometheus + Grafana |
| Инфраструктура | Docker Compose, nginx, Let's Encrypt |

## Как это устроено

Монорепозиторий на NX, backend разбит на независимые микросервисы:

```
apps/
├── user-service          — регистрация, вход, пользователи, роли, права доступа
├── ticket-service         — тикеты, SLA, вложения, email-канал, автоматизация, кастомные поля
├── chat-service            — Socket.IO: чат, присутствие, живые уведомления
├── knowledge-service    — база знаний, полнотекстовый поиск (Elasticsearch)
├── analytics-service     — отчёты и аналитика
└── notification-service — фоновая отправка email-уведомлений (BullMQ)

frontend/
├── client-portal   — приложение для клиентов (публичный домен)
└── operator-app     — приложение для персонала (путь /staff/)
```

Все сервисы стоят за nginx, общаются друг с другом напрямую и через Redis (pub/sub для мгновенных live-обновлений, BullMQ — для того, что обязательно должно быть доставлено, даже если получатель сейчас офлайн).

## Полный список возможностей

### Тикеты
- Создание тикета с темой, описанием, приоритетом и вложениями (до 35 МБ на файл, с проверкой типа по содержимому файла, а не только по расширению)
- Жизненный цикл статусов: **В работе → Ожидание / Передано разработчикам → Завершено**, с возможностью повторно открыть переданный разработчикам/завершённый тикет; новый тикет сразу создаётся со статусом «В работе»
- Приоритеты: низкий / средний / высокий / срочный
- Назначение исполнителя и отдела, история всех изменений (кто, когда, что поменял)
- Объединение дублирующихся тикетов в один, с сохранением истории обоих
- Метки (теги) для произвольной классификации, быстрый фильтр и отчёт по меткам
- Кастомные поля на бланке тикета: текст, число, дата, чекбокс, многострочный текст, поле с проверкой по regex-шаблону, поле-файл, зависимые/иерархические выпадающие списки («категория → подкатегория»)
- Полнотекстовый поиск по тикетам (с подсветкой совпадений)
- Список тикетов: фильтры по статусу/приоритету/исполнителю/отделу/меткам, фильтр «Неприсвоенные», сохранённые пресеты фильтров, настраиваемые колонки таблицы, поиск по номеру/теме/автору, массовые действия (ответить/назначить/объединить/завершить/удалить)
- Корзина с мягким удалением и восстановлением
- Экспорт переписки по тикету в текстовый файл
- Приём тикетов по email — входящее письмо от нового адреса создаёт тикет и клиента автоматически, ответ в том же цепочке писем добавляется как сообщение, а не создаёт дубликат

### Общение в реальном времени
- Чат по каждому тикету — сообщения, форматирование текста, редактирование своих сообщений
- Внутренние заметки — видны только персоналу, клиент их не видит
- Индикатор «печатает…», баннер «сейчас просматривают» (клиент видит, что оператор открыл его тикет, и наоборот)
- Упоминания коллег через `@имя` в сообщении — упомянутый получает уведомление и live-пуш
- Заготовки ответов (макросы) с подстановкой имени клиента/оператора и номера тикета
- Живые тосты о новых и переназначенных тикетах, подсветка соответствующей папки статуса в сайдбаре
- Статус присутствия сотрудника — онлайн/офлайн, кастомные статусы (например «Обед», «Совещание») с автоматическим переходом в «Неактивен» при бездействии

### База знаний (FAQ)
- Публичные статьи, доступные без регистрации
- Полнотекстовый поиск по статьям
- Счётчик просмотров, сортировка «популярное»/«новое»
- Анонимная оценка «полезно / не полезно»
- Кастомизация оформления публичных страниц базы знаний (свои CSS и JS, только для администратора)

### Оценка качества (CSAT)
- Опрос удовлетворённости после закрытия тикета — баннер прямо в теле тикета
- Список вопросов настраивается администратором
- Отчётность: средний балл, разбивка по операторам и по вопросам

### Отчёты и аналитика
Раздел «Отчёты» с несколькими независимыми разделами:
- **Дашборд** — тикеты по статусам, среднее время ответа/решения, % соблюдения SLA
- **Конструктор отчётов** — гибкая группировка (по сотруднику/клиенту/отделу/компании/типу/периоду), взвешенный KPI, фильтры по меткам и кастомным полям, экспорт CSV/XML
- **Отчёт в динамике** — тренд по периодам
- **Отчёт по операторам** — время в каждом статусе присутствия, скорость возврата в диалог, % решений с первого ответа (FCR)
- **CSAT-отчёт** — удовлетворённость клиентов
- **Аудит тикетов** — кто и что менял в конкретных тикетах
- **Аудит настроек** — кто и когда менял SLA-политики, права доступа, кастомные поля, правила автоматизации
- Экспорт в CSV/XML доступен во всех разделах

### Автоматизация («Диспетчер»)
- Правила «триггер → условие → действие»: при создании тикета, смене статуса/приоритета, ответе клиента или нарушении SLA — сменить статус/приоритет, назначить отдел или исполнителя, проставить значение кастомного поля
- Вычисляемые поля по формуле со ссылками на другие поля

### SLA
- Политики времени ответа и решения по каждому приоритету
- Автоматическая эскалация (повышение приоритета) при нарушении срока

### Права доступа и безопасность
- Три роли: клиент / оператор / администратор
- Группы прав поверх ролей: ограничение по отделам, режим «только свои тикеты», роль «наблюдатель» (не может быть исполнителем)
- IP-белый список для входа
- Двухфакторная аутентификация (TOTP) — по желанию сотрудника или обязательно для целой группы прав
- Корпоративный вход через AD (LDAP) или SSO (OIDC — Entra ID/Azure AD, Okta и др.) — отдельно для сотрудников и для клиентов, с автосозданием аккаунта при первом входе
- **Подтверждение регистрации администратором** — новый клиент не получает доступ сразу: заявка попадает к администратору (колокольчик с счётчиком в сайдбаре), пока не будет нажато «Активировать»
- Мгновенное завершение сессии при деактивации сотрудника или клиента администратором — даже если у человека была открыта вкладка

### Контакты и организации
- Карточка клиента: ФИО, email, телефон, компания, отдел, должность, город
- Экспорт контактов в CSV
- Поиск и слияние дублирующихся карточек клиентов
- Отчётность в разрезе компании

### Интерфейс
- Тёмная и светлая тема
- Три языка интерфейса: русский, украинский, английский
- PWA (клиентский портал можно установить на устройство)

### В разработке
Пока не реализовано, в планах: слэш-автодополнение макросов в поле ответа (подстановочные теги уже работают), исходящие вебхуки во внешние системы.

## Инструкция для нового пользователя (клиента)

1. **Откройте портал** и нажмите «Зарегистрироваться».
2. **Заполните форму** — имя, email, пароль (минимум 8 символов).
3. После отправки формы откроется экран ожидания: *«Запрос на регистрацию отправлен администратору. Ожидайте минутку…»* — это нормально, доступ к системе открывается только после подтверждения администратором.
4. Как только администратор подтвердит заявку, экран **сам, без обновления страницы**, переключится на зелёную галочку «Добро пожаловать в Ticket Desk», и вас автоматически перенаправит в личный кабинет — уже вошедшим в систему.
5. **Создайте тикет**: кнопка «Новый тикет», заполните тему, опишите проблему, при необходимости приложите файл.
6. **Общайтесь с оператором** прямо в тикете — ответы приходят в реальном времени, без обновления страницы.
7. Следите за статусом тикета — он меняется автоматически, как только оператор его обновит.
8. После того как тикет закрыт, **оцените качество поддержки** — баннер с предложением оценить появится прямо в тикете.
9. Если нужен быстрый ответ на типовой вопрос — загляните в раздел **«База знаний»** (доступен и без регистрации).

Альтернативный способ создать тикет — просто написать письмо на адрес поддержки: письмо само превратится в тикет, а ответы будут приходить туда же на почту и одновременно отображаться в портале после входа.

## Возможности оператора

Оператор видит очередь тикетов (по умолчанию — своего отдела, если для его группы прав включено ограничение) и работает с ними:

- Просматривать и фильтровать список тикетов (статус, приоритет, исполнитель, отдел, метки, «Неприсвоенные»), пользоваться сохранёнными пресетами фильтров
- Открывать тикет, менять статус/приоритет/исполнителя/отдел
- Отвечать клиенту в чате — с форматированием текста, вложениями, редактированием своих сообщений
- Оставлять внутренние заметки, невидимые клиенту
- Использовать заготовки ответов (макросы) и упоминать коллег через `@имя`
- Ставить метки на тикеты, объединять дубли, экспортировать переписку
- Заполнять и просматривать кастомные поля тикета
- Видеть карточку клиента (read-only) и историю его предыдущих тикетов
- Работать с базой знаний — создавать и редактировать статьи
- Выполнять массовые действия над несколькими тикетами сразу
- Восстанавливать удалённые тикеты из корзины
- Устанавливать свой статус присутствия (Онлайн / кастомный статус), переключать тему оформления и язык интерфейса
- Если группе прав открыт доступ — пользоваться разделом «Отчёты»

## Возможности администратора

Администратору доступно всё, что и оператору, плюс управление системой целиком:

**Пользователи и доступ**
- Создавать учётные записи сотрудников (в отличие от клиентов, которые регистрируются сами)
- Редактировать карточки пользователей, деактивировать/восстанавливать, сбрасывать пароль и 2FA
- **Подтверждать или отклонять заявки на регистрацию** новых клиентов — через колокольчик в сайдбаре
- Настраивать группы прав: ограничение по отделам, «только свои тикеты», роль «наблюдатель», IP-белый список, обязательная 2FA для группы
- Просматривать и восстанавливать дубли контактов, экспортировать базу клиентов в CSV

**Настройка процессов**
- Управлять отделами (командами)
- Настраивать SLA-политики (сроки ответа/решения по приоритетам)
- Создавать правила автоматизации («Диспетчер») и вычисляемые поля
- Управлять кастомными полями тикетов (типы, обязательность, зависимости, условная видимость)
- Управлять метками, макросами, каталогом кастомных статусов присутствия
- Настраивать список вопросов CSAT-опроса
- Настраивать веса типов тикетов для расчёта KPI в отчётах

**База знаний**
- Публиковать и снимать с публикации статьи
- Настраивать оформление публичных страниц базы знаний (собственные CSS/JS)

**Отчётность и аудит**
- Полный доступ ко всем разделам Хаба отчётов (дашборд, конструктор, динамика, по операторам, CSAT, аудит тикетов)
- **Аудит настроек системы** — журнал того, кто и когда менял SLA-политики, права, кастомные поля, правила автоматизации

**Только администратору**
- Создание учётных записей сотрудников
- Подтверждение/отклонение регистраций
- Управление правами доступа и группами
- Управление отделами, SLA, автоматизацией, кастомными полями, весами KPI, статусами присутствия, вопросами CSAT
- Оформление базы знаний (CSS/JS)
- Аудит настроек системы
